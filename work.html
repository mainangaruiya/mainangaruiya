BomaLens

Multimodal AI Property Intelligence — Nairobi Market

The Problem

Nairobi property listings are unstructured by default — agents upload photos with no metadata, no geo-coordinates, and no consistent fields. Buyers scroll through WhatsApp forwards and static PDFs. There was no pipeline that could look at a photo of a house and output structured, searchable data: beds, bathrooms, condition signals, rough location. Everything that should be a query was a manual scroll.

What I Did

  • Built a FastAPI extraction endpoint that accepts a property photo, runs it through Gemma (multimodal) and returns a structured JSON payload — bedrooms, bathrooms, estimated condition, inferred property type, and a confidence score. Gemma over a wrapper API because it runs self-hosted; extraction calls don't leave the stack, and cost per inference stays flat regardless of volume.
  • Stored results in PostgreSQL 16 with PostGIS — not a flat lat/lon pair. PostGIS because Nairobi searches are radius-based ("near Kilimani", "within 2km of Westlands"), and those need ST_DWithin on a geometry column, not table scans with haversine arithmetic in application code.
  • Rendered listings on a Leaflet/Mapbox GL map in a Next.js/Tailwind PWA — mobile-first because agents and buyers in this market are almost exclusively on phones, often on patchy connections. Installable PWA means it behaves like a native app without an app-store dependency.
  • Containerised the full stack — Next.js frontend, FastAPI backend, Postgres+PostGIS — in Docker Compose so the whole environment spins up in one command.

What Came of It

A photo is now a database row in under three seconds. Agents can upload listing photos and get structured, mappable records without filling in a form. The PostGIS layer means any radius or polygon search is a single indexed query. Proved that a self-hosted multimodal model can replace a manual data-entry step end-to-end — same pattern applies anywhere unstructured visual input needs to become ranked, searchable output.
